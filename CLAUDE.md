# Campaign Command Center

Static campaign dashboard for True Lean Solutions / TechTranspire, published to GitHub Pages and refreshed daily from Zoho CRM.

## Layout

## How the page is built
- The page code talks to a small `window.dash` data layer at the top of `index.html`: `dash.loader` turns each raw Zoho answer into rows, `dash.calc` derives values from datasets, `dash.data(id)` reads them, and `dash.onData(fn)` redraws.
- Every data source is merged by `mergeDatasets` in that layer, in order: the defaults (`DS_DEFAULTS`, empty lists for datasets a build may not carry), then `data.js`, then `boxbyte.js`, `courier.js`, `research.js`, `mail.js`, `cal.js`, `ff.js`, `linksync.js`, `p3.js` and last the opened sealed file (`window.__SEALED__`). A later source wins, so the sealed file overrides a snapshot branch for the same dataset — except that an empty list never replaces rows an earlier source supplied (Hemang, Nov 8, 2026). That exception is what makes it safe to run two pipelines into one dataset during the Chief of Staff changeover: a feed run that returns no rows leaves the branch file's data standing instead of silently blanking a panel. `window.__DASH_SOURCES__` records, per dataset, which source won and how many rows it brought, so a build can be checked from the browser console.
- Dataset IDs in `QUERIES` (fetch script) must match the `dash.loader(...)` IDs in the page.
